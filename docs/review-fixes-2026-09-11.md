# 第二轮复查修复记录

本轮针对复查确认的四项问题，按项目恢复、图表交互、研讨总结三个独立范围并行处理。此前测试结果是当时覆盖场景的验证记录，不代表项目不存在其他缺陷。

## 修复范围

1. **临时断网丢失成果引用**：服务器数据校验暂时失败时，保留研讨会话、事件序号、纪要、图表和 PPT 引用，仅暂停依赖数据确认的后续操作。联网刷新且数据版本一致时恢复使用；真实版本变化、取消确认、数据过期仍按原规则使成果失效。
2. **新图失败仍可确认旧图及请求竞态**：推荐、生成、确认统一管理操作状态；新请求开始即使旧预览失效，失败不会将旧图与新口径拼接。切换项目或离开页面后不接收旧请求结果。
3. **异常总结伪装成功**：结构或内容校验失败时返回可恢复错误，保留研讨记录，不填入通用对策，不发出完成事件。恢复操作重新执行总结。
4. **总结遗漏早期信息**：最终总结请求携带完整研讨历史；普通讨论轮次仍使用最近发言。异常重试同时持久化轮次计数标记，防止重复计数。

## 验证设计

- 项目恢复测试使用真实 IndexedDB 测试实现，模拟多次离线保存后联网，核对成果引用、事件记录和路由限制。
- 图表组件测试覆盖替换预览失败、推荐请求等待期间的按钮限制、切换项目和卸载后的过期响应。
- 后端测试覆盖非法 JSON、拒答文本、缺少字段、空白总结、错误后的恢复及完整历史输入。
- 六步浏览器流程增加总结失败后的恢复，以及生成成果后数据接口暂时不可用、刷新恢复、再次访问成果页的场景。

## 运行边界

最终总结采用一次完整历史请求，不静默截断，也不自动增加分段模型调用。历史超出所选模型上下文或预算限制时会明确失败并保留记录；没有进行真实付费模型联调。
