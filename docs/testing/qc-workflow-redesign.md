# 以章节为中心的QC工作流程

## 判断
现有后端已具备章节路径、资料版本、上游依赖与导出预检，无须重建数据架构。主要问题在前端：选题后跳数据、数据后跳研讨，以及把访问页面当完成进度，会引导用户走旧的六步报告流程。

## 实施
主流程：确定课题 → 逐章编写 → 成果检查与导出。
辅助工具：资料与数据、图表工具、数据研讨、模型配置，可随时进入。

- 确认选题直接进入章节工作区，不要求先上传Excel。
- 数据确认只确认当前数据；用户自选进入数据研讨或回到章节。
- 主导航仅展示位置，不将访问顺序伪装为完成状态。
- 章节目录及当前章节写作是工作区主体，场景、资料、活动记录收进辅助区域。
- 已有章节内的表和图直接导出，不要求到图表工具再做一遍。
- 成果页保留章节预检及草稿导出；旧流程成果收起，供历史项目使用。
- 保留原路由、项目ID、数据及版本，不迁移或删除历史项目。

## 边界
数据研讨仍需要确认的表格，是针对数据的辅助分析，不取代逐章写作。实际完成度以保存内容、作者审核和待复核状态计算。模型配置只在调用模型时需要，不阻止手工编写。

## 验证

前端原64项测试通过，新增主流程导航测试通过；生产构建与lint通过。使用test模式构建运行完整辅助数据流程端到端用例通过，覆盖选题进入章节、数据预览与确认、研讨恢复、图表、历史成果下载及刷新恢复。浏览器检查主导航与章节工作区，保留原有对话。
