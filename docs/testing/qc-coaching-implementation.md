# QC顾问定向规则与交付规范

本轮按用户逐章说明、T/CAQ 10201-2020和35页获奖案例实施。这里的“调教”是可审查的提示规则、章节上下文和图表生成能力配置，不是模型权重微调。规则直接由后端使用，无须另装全局skill。

## 依据与优先级

- 标准：PDF第10–12页，4.1.2–4.1.12；关键条文已视觉核对。
- 用户偏好：人、机、料、法、环五方面通常各1–3项末端因素；各章有数据表、适当图表和结论；要因确认后单独汇总。数量、固定图形及单独汇总小节属于成果表达偏好，不冒充标准硬要求。
- 案例：选择课题4–5页，现状6页，目标7页，原因8页，逐项确认9–22页，对策23页，实施24–28页，效果29–32页，巩固33页，总结34页。研究笔记见 qc-standard-study.md 和 qc-award-study.md。

## 选题顾问分流

无意向：从工作/兴趣方向开始，每次一个问题，必要时给2–3项选择，不先问数据。
已有意向：立即进入选择课题的理由和差距数据，不再把用户引向运输、施肥、剂量等后续原因或措施。用户让直接拟稿时，给拟议理由和对比数据，保留模拟性质。
只负责选择课题，不抢做现状症结、要因确认和实施方案。历史里顾问提出的建议不等于用户选定。

## 各角色职责

- **moderator**：主持人只确定当前章节、梳理已知结论和一个待决问题，防止跨章跑题；不代替分析师计算或代替用户确定要因。
- **researcher**：研究员负责查明对标依据、标准适用范围、可引用来源及缺项，不把案例数值当作本项目实测，不越权选定课题或对策。
- **analyst**：分析师负责同口径对比、分层频次、最大症结、目标测算与影响程度计算，给数据表和适合的图表；原因分析阶段的猜测不能写成已确认要因。
- **critic**：评审只检查当前章及其上游衔接：依据是否支撑结论、最大症结是否被偷换、判据是否测影响程度、图表和正文计算是否一致。给出具体改法，不泛泛拒绝模拟草稿，也不代写后续章节。
- **writer**：撰稿人负责按当前章节职责组织数据、表格、图和结论；依照已选课题和最大症结展开，有数据论证且内容充实，不重复选题，不抢写下一章。
- **data**：清洗顾问只说明数据质量、单位、缺失、重复及拟议修订，不代替选题、要因确认或对策设计；原始记录与模拟版本分别保留。
- **chart**：图表顾问只将当前章节数据转为合适图表并解读：差距用对比图，症结用分层/排列图，实施及效果用前后对比，巩固用趋势图。不补造原因或把相关性写成已证实因果。

## 逐章交付

### 小组概况

说明小组、人员分工和活动安排，未知实名与注册信息保留待填

交付：活动范围、职责、计划；不替代选题理由。

图表：成员职责表、活动计划表。

向后传递：课题适用对象与组织边界。

### 选择课题

围绕用户已有意向，用当前指标与有来源的标准、同行或组织历史最佳水平作同口径比较，量化差距并说明选题必要性；没有实据时可拟模拟对标数据并标注。不得提前转向原因、对策或要求重新选方向

交付：明确课题名称、选题理由、现状/对标/差值/来源比较表及结论。

图表：差距比较表、基线与对标柱状图。

向后传递：选定课题、核心指标及单位、基线、对标依据、调查范围。

### 现状调查

课题选定后调查不良表现，按大方面分层统计频次、比例和累计比例，定位影响最大的症结。此处不是细化人机料法环末端原因

交付：调查对象、时期、样本口径、分层统计表、排列图及明确的最大症结与占比。

图表：调查表、分层法、排列图。

向后传递：最大症结及其指标、频次/分母/占比，基线及目标测算输入。

### 设定目标

目标与课题一致；依据对标、组织历史最佳水平或症结预期解决程度给测算过程。频次占比不直接等于产量提升比例，使用贡献比例须解释关系和假设；自定目标无需独立目标可行性论证章

交付：基线、目标值、单位、时限/统计期；依据与算式；简洁明确的目标陈述。

图表：目标依据表、基线与目标对比图。

向后传递：固定目标与口径、最大症结、预期改善程度。

### 原因分析

严格针对前章最大症结展开因果链。按用户偏好从人、机、料、法、环五方面逐层细化，每方面通常1至3项具体、可验证、可采取措施的末端因素，必要时补测量维度。禁止只写管理不到位、意识不强等大词；此阶段不能直接判要因。五方面与数量是用户模板偏好而非标准硬规定

交付：中心症结→维度→中间原因→末端因素的因果图/原因树，以及带编号的完整末端因素清单。

图表：原因树、末端因素表。

向后传递：唯一最大症结、每个末端因素编号及因果路径。

### 要因确认

逐一对应原因分析的全部末端因素，识别能力范围外因素。先做确认计划表：末端因素/确认内容/方法/影响程度指标/确认标准及依据/负责人/时间；再按因素逐项展开实施：设计对照、对象样本、控制条件、实测或模拟数据表、图、影响程度计算、按预设判据判要因或非要因。确认的是对最大症结的影响程度，不是只看因素是否存在或是否合格；不预设结论、不先做对策再倒推原因。最后必须独立给要因确认汇总表，归档要因

交付：全部末端因素逐项确认记录+数据图表+影响程度判定；要因/非要因/待确认汇总及已确认要因列表。

图表：要因确认计划表、逐项对照数据表、影响程度对比图、要因确认汇总表。

向后传递：已确认要因及编号、影响程度、证据、未确认项。

### 制定对策

只围绕确认的要因制定5W1H对策表：要因/对策/简明可测目标/分点措施/地点/时间/负责人。措施必须写具体操作、设备参数、顺序及检查办法，可直接交现场执行；不以加强管理、提高意识代替措施。必要时比较多种对策

交付：每项要因对应的可执行对策表，措施逐项编号，目标与验收口径明确。

图表：方案比较表、5W1H对策表。

向后传递：编号对策与编号措施、局部目标、验收方法。

### 对策实施

严格按照对策表每项分点措施依次展开实施，写操作对象、步骤、参数、责任/时间和现场记录。每项对策完成后给数据表与图，对比其局部目标；未达目标写调整及复查。必要时补安全、环境、质量、成本等负面影响验证，不编造检测报告

交付：逐项实施叙述、对应数据表/图、局部效果结论和可选照片说明；模拟过程明确标注。

图表：实施过程表、对策目标与结果对比图、调整复查表。

向后传递：每项对策实施结果、最终效果检查的对象和统计期。

### 效果检查

同时检查课题总目标与最大症结：实施前/目标/实施后三组指标数据图表，以及症结前后频次或比例变化；统一分母、观察期、单位，不能用样本量变化制造改善。给计算与达标结论，照片可辅助不能替代数据

交付：课题达标对比表与图+最大症结改善对比表与图+改善幅度、限制和必要的效益分析。

图表：前后对比表、目标达成柱状图、症结变化图。

向后传递：有效措施、达标情况、需要持续观察的症结指标。

### 巩固措施

将已证明有效措施转化为作业标准/制度及批准状态，围绕最大症结设置持续监测。给多个后续观察期数据和趋势图，按明确容许波动说明有无反弹；未经过巩固期只能写计划或模拟，不能冒称已巩固

交付：标准化措施表、批准/执行状态、巩固期跟踪表与趋势结论。

图表：巩固措施表、跟踪数据表、趋势图。

向后传递：稳定性结论、保留的问题与后续改进方向。

### 总结和下一步打算

按专业技术、管理方法、成员素质等方面简洁总结收获与不足，用表格呈现；下一步研究方向从本次不足或尚未解决问题提出，不重复全篇，不无依据保证未来效果

交付：收获与不足表，下一步方向及理由。

图表：总结对照表。

向后传递：下一轮拟研究方向。

## 数据、图表与连贯性

允许模拟数据和模拟实施稿，简短标注simulation；真实依据和假设参照分开。未知行业阈值不能包装成正式标准，不能虚构第三方报告、批复或他单位实绩。图表、表格、正文必须使用一致数值和口径。

生成每一章时带入同项目之前各章的最新版本、审核状态、数据性质及内容，排除其他项目和后续章节。这样原因分析承接现状最大症结，制定对策承接要因确认，实施承接具体措施。前章变更时，已生成后章标为待复核。

章节输出支持正文、结构化表格、条形/折线/排列图，保留JSON可编辑源数据；展示和PPT使用同一份块数据。图后需要解释观察结果及本章结论。原因树暂可通过因果路径表完整呈现，不能把图形数量当作内容质量。
