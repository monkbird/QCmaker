# QC 工作台升级与恢复

本轮仅在独立测试库执行迁移，未启动正式服务、未迁移用户现有数据库。

## 升级前备份

1. 停止 QCmaker 后端及所有写入进程。
2. 将完整 `backend/data`、上传目录、生成成果目录及部署使用的 `.env` 复制到带时间戳的独立备份目录。保留 SQLite 的 `-wal`、`-shm` 文件，不在运行中只复制主数据库。
3. 用 SQLite backup API 从备份副本建立验证库；先在该副本执行启动迁移及完整性检查，确认项目、资料、数据集和下载记录数量。
4. 另行导出浏览器 IndexedDB 或保留浏览器配置目录。前端升级至版本 2 会迁移原项目快照，不要求清空浏览器数据。

## 迁移行为

保留原 v1 SQL 与校验和；新增 v2 表在单个事务中顺序执行，任一步失败回滚，不记录成功版本。重复启动只校验版本及校验和。高于程序支持范围的版本直接拒绝启动。

失败时保存错误日志并恢复旧程序。新程序已写入数据后，不能直接用旧程序继续写新库；必须停止服务，将数据库、资料及成果目录作为一套从升级前备份恢复，再使用对应旧程序。恢复会放弃备份之后的修改，操作前应另存当前目录以便人工核对。

本地回归验证包含：真实 v1 表结构与旧数据、v2 部分失败回滚、重试、重复启动及校验和。测试不会打开用户唯一数据库。
