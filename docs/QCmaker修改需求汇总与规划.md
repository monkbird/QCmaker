# QCmaker 修改需求汇总与规划

## 一、文档定位与实施边界

本文汇总本轮项目核查和用户已确认的修改要求，作为后续实施依据。本文描述的目标能力尚未实现，不能作为当前功能说明或验收通过证明。

本次仅整理文档，不修改业务代码。配置、资料读取及选题相关要求先行明确；现已通读用户提供的 T/CAQ 10201—2020 扫描件，并补充条文解读和项目差距。另已检索到发布机构关于新版替代旧版的公告，正式实施前需核定适用版本和申报要求，再制定详细方案，由用户安排实施。

需求状态分为：**已确认要求**、**标准依据（注明版本）**、**建议方案**、**待核实事项**。原文中的“待规范明确”事项按本次核对结果更新；标准要求不等于已经确定的软件实现方案，建议方案不得视为用户已经确认的最终交互设计。

### 1.1 细化文档与并发实施入口

按用户要求，已将本总纲细化为[并发任务包与阅读入口](superpowers/plans/2026-09-16-qcmaker/README.md)，包括公共约定、配置与模型、资料与清洗、逐章编写与审核、图表与导出、统一集成与迁移六个任务包。各包明确拟修改文件、依赖、输入输出、审核及验收条件，便于后续分派多个子代理。

本总纲继续作为业务要求和标准依据的主文档；任务包中的表、接口及交互属于建议实现方案，实施前统一核对并冻结，不等于已经实现或已确认最终设计。公共文件由协调者集中处理，领域包按文件归属并行。本次仅改文档，不安排子代理修改代码、不执行迁移或业务测试；后续代码实施由用户另行安排。

## 二、总体调整方向

现有“配置—选题—数据—研讨—图表—成果”六步工作台，将多个 QC 活动阶段压缩到同一数据和研讨流程，不能充分表达阶段证据、现场验证和实施后的效果检查。

已确认：产品以 **QC成果编写** 为主，支持少资料或无资料起步，由作者指定场景或课题，结合联网研究、资料整理、AI分析及逐章审核形成报告。按问题解决型QC程序组织章节和论证，不要求作者按照现场活动实时进度操作，也不把完整Excel作为开始写作的前提。数据、资料、分析和图表服务于各章节，可以随讨论补充、复用和调整。

报告中的活动时间、过程数据和结果关系仍须核对：什么时候调查、什么时候实施、经过多长时间观察效果、哪些数据对应哪些措施，以及变化是否足以支持结论。软件操作顺序、资料上传顺序与实际活动时间分别管理，不能因编写顺序灵活而忽略报告时间逻辑。

用户提出的流程基线为：确定课题、现状调查、设定目标、原因分析、要因确认、制定对策、对策实施及效果检查、巩固措施和总结展望。按所提供的2020版，需区分自定目标与指令性目标，将“对策实施”和“效果检查”作为不同活动步骤，将“制定巩固措施”和“总结和下一步打算”分别管理；完整程序见第十章。暂不确定最终页面数量，也不强制保留六步结构。创新型已纳入标准学习范围，是否纳入软件本轮实施范围尚未确认。

用户样例采用“小组概况＋问题解决型自定目标的十个活动步骤”，共十一部分，可作为报告组织基线；不能把小组概况解释为标准额外规定的活动步骤。软件按章节逐步成稿和审核，不必整篇生成完再交作者判断。第十章保留标准解读，软件草稿生成和审核规则见第五、七章，二者不混写。

## 三、配置界面修改

### 3.1 多套配置与持久保存【已确认要求】

当前配置通过手动保存写入后端配置文件，只保存当前值；主模型、凭据库、角色分工各有保存按钮，没有多套方案切换，也没有未保存草稿保护。

目标要求：

- 支持整套配置命名保存、选择和切换，重新打开后恢复当前方案。
- 配置方案涵盖默认模型、角色模型分工、服务配置及搜索配置的关联。
- 明确当前方案、已保存状态和未保存变更，避免误以为“保存并继续”已提交所有分区。
- 密钥不回显，存储位置说明应符合实际部署；远程部署不得继续笼统声称“只存本机”。

建议方案：统一保存入口；切换前处理未保存内容；方案引用独立凭据记录，避免无必要复制密钥。历史版本、方案删除和恢复方式在实施设计时确定。

### 3.2 Coding Plan 与可选默认模型【已确认要求】

当前允许在主模型位置选择部分 Coding Plan 服务，但仅配置凭据库和各角色、主模型留空时，会被就绪状态及流程门禁挡住。部分无角色调用仍依赖默认主模型。

目标要求：

- 可以先保存 Coding Plan／服务配置，再给各角色选择该服务可用的模型。
- 默认主模型改为可选；未配置默认模型时，按实际业务环节检查角色是否完整。
- 配置缺失时指出具体角色或能力，不再统一要求填写 OpenAI Key。
- 审计所有模型调用入口，消除角色已分配但实际仍使用默认模型的隐式依赖。
- 资料基本读取不以套餐提供向量化能力为前提；需要向量化时独立检查相应能力。

套餐接口、模型列表和实际调用能力需实测，不能凭服务商已被收录就认定可用。模型接口适配范围在实际接入时核定。

### 3.3 模型清单与统一调用验证【已确认要求】

当前服务商名称及默认地址为预置目录，模型 ID 向服务商 API 获取；角色列表可能使用当前页面缓存。列表返回成功不代表账号有权调用全部模型。

目标要求：

- 保留底部“测试连接”作为统一测试入口，不新增角色旁的调用测试按钮。
- 对当前分配给所有角色的模型及已配置的默认模型发起真实最小请求。
- “跟随默认模型”的角色也纳入检查；全部角色通过才能显示整体通过。
- 显示每个角色对应的服务、模型及测试结果，失败时说明具体原因。
- 相同服务地址、凭据和模型的请求可合并测试，结果映射回各角色。
- 测试基于当前待保存配置；配置变更后旧结果不能继续代表新配置已通过。
- 未选用的模型不批量调用；明确真实调用会产生少量消耗。

用户已明确不加入上一轮提出的“角色刷新按钮强制重新拉取并显示获取时间”修改项。

### 3.4 Tavily 与联网检索【已确认要求】

当前 Tavily 已有实际搜索调用代码，但缺少真实密钥环境的成功验证；研究员会调用搜索，选题顾问尚未接入。无密钥或搜索失败时返回空结果，前端无法充分辨别原因。

目标要求：提供申请入口、明确搜索服务状态和真实搜索验证；区分未配置、调用失败及无匹配结果。用户不需要提供自有网站或目标网址。

少资料与无资料起步均需联网检索，不能只在完全没有上传材料时才启用搜索。有资料时先读资料，结合场景和缺口补充外部依据。搜索不可用时明确限制，可以保留或讨论框架，但不能声称已完成检索或给出假装查证过的事实结论。搜索验证与模型连接测试属于不同能力，应分别呈现结果。

检索用于选题、指标解释、技术原理、对标水平、原因分析和措施适用性等，不限于查找同类QC成稿。应核对来源、发布时间、地域、环境和对象条件；不能把异地或不同工况的结果直接套用。场景框架和检索维度见5.5节。

## 四、上传资料与中文完整读取

### 4.1 当前缺口

- 现有解析支持 DOCX、XLS/XLSX、PPTX、PDF、TXT、Markdown、CSV，但主要提取文本和部分表格。
- 扫描页、图片文字、图表视觉含义等未完整覆盖；旧版 DOC/PPT 不在支持范围。
- 表格资料存在行数截断；上传入库还依赖向量化服务。
- 不能将格式允许上传、解析未报错或成功切分，等同于内容完整且正确。

### 4.2 目标要求【已确认要求】

- 上传后直接读取，基本阅读不依赖向量化服务。
- 对已承诺支持的文档，完整处理正文、表格、备注、扫描页、图片文字等内容；长文档分批处理，不静默截断或遗漏。
- 针对中文编码、字体映射、扫描质量及复杂表格选择合适解析路径，必要时使用 OCR 或视觉识别交叉核对。
- 提供解析预览和来源定位，检查乱码、漏字、错行、表格错位及未解析区域。
- 遇到异常自动尝试其他可用方式；仍不可靠时明确定位，不猜补，不标为成功读取。
- 保留原始资料，派生文本和结构数据可追溯、可重建。

用户的验收目标是“全部内容读取正确”。实施方负责技术方案，不要求用户选择解析工具。不能以安装一个 skill 代替应用能力实现，也不能在未经核验时保证任意文件绝对无误。

建议验收方法：建立中文文档样本集，涵盖不同字体、编码、扫描件、混排及复杂表格，逐页或逐表核对内容覆盖与准确性。具体样本和受支持格式清单在实施前明确，旧版 DOC/PPT 是否补齐应列入覆盖范围讨论。

### 4.3 解除文件大小限制【已确认要求】

- 取消参考资料上传的 ≤10MB 限制，同步检查前端、后端、部署层及界面说明。
- 大文件显示上传和解析进度；失败给出原因，不用静默截断替代完整处理。
- 取消固定限制不等于忽略实际资源边界；大文件的流式处理、分批解析与恢复机制需在实施方案中落实。
- 数据页另有 10MB、5000 行、200 列及 Excel 解压大小限制，需在数据模块重构时统一审视；本轮明确取消的是参考资料上传的 10MB 限制，不将其他限制的具体处理方式视为已定。

### 4.4 统一资料入口与人工把关的清洗【已确认要求】

允许上传任何对QC编写有帮助的材料，包括研究总结、验收意见、标准、案例、照片、表格、会议记录，以及支持或质疑某项原因的资料。不按“只能用于选题”或“必须是数据表”限制材料用途；具体文件格式以明确承诺且验证通过的支持范围为准，不将“任意辅助材料”误写成任意格式均已支持。

不要求作者另行准备Excel。正文、PDF表格、图表及图片中的信息可以提取为可引用事实或结构化数据；原资料、提取结果和来源位置同时保留。资料入口应贯穿编写过程，可早期集中上传，也可后续分批补充。

清洗和分析分为三类，处理结果由作者把关：

| 类别 | 处理内容 | 人工核对重点 |
|---|---|---|
| 文档整理 | 识别文字、表格、图片，去重，提取事实及上下文 | 有无漏读、错字、错行，是否丢失限定条件和图表含义 |
| 数据处理 | 统一单位、日期及字段，检查缺失、异常、重复和计算 | 修改前后值、处理依据、影响范围；保留原始值，可撤销 |
| 证据分析 | 判断资料适用章节、支持或质疑的结论，以及来源冲突 | 适用对象、时间、条件和推断力度；不为强化某个结论而静默删除反向证据 |

AI先提出处理方案和差异预览，作者确认后应用。低风险格式整理可批量确认，涉及数值、单位转换、样本删除或结论变化时突出显示。具体交互形式在详细设计时确定。

### 4.5 清洗后资料的章节匹配与复用【已确认方向】

- 根据已选课题、当前章节目的和讨论结论，自动提取并推荐可用资料，显示来源位置、推荐用途及适用条件，由作者确认重要引用和结论。
- 同一资料可供多个章节使用；区分原文事实、计算结果和分析判断，不因跨章引用改变采样对象、时间或估测／实测性质。
- 新增资料作为补充保存，不默认替换此前全部数据；同一数据不同版本保留关联。
- 作者修改课题、分析方向或清洗规则后，重新匹配受影响内容，提示相关文字、图表与结论待复核，不要求整篇重来。
- 作者审核后的内容与资料版本相绑定，不能在资料已改变时继续沿用旧的通过状态。

自动归属、关联保存及影响分析由实施方设计，不要求作者手工给每份材料逐项建立关系；数据库和接口方案尚未落定。

## 五、选题顾问、场景检索与生成边界

### 5.1 全文阅读与资料优先【已确认要求】

当前每次提问仅检索最多三个片段，每片段最多取三百字符，不是全文阅读。检索异常时仍可继续生成回答。

目标要求：

- 先完成全部上传资料的读取，再作答；长资料分批阅读并建立可追溯的来源索引。
- 将资料解析完成、内容阅读完成和本次回答采用的证据分别记录，不能用切片数量冒充全文理解。
- 当前资料未读完或存在解析失败时明确告知，不能声称已经完整阅读。
- 优先使用用户资料；少资料和无资料起步均联网检索，补充场景与论证依据，并区分外部来源和本项目事实。
- 搜索失败或证据不足时说明限制、提出需要补充的信息，不生成假装经过查证的事实结论。
- 不重复无必要的全文读取：可复用已经核验的资料版本和阅读记录，但新增或修改资料必须重新处理相应内容。

### 5.2 忠实读取与草稿生成的边界【已确认要求】

用户已澄清，原“禁止编造”的资料约束重点针对上传文档对选题和判断的影响：应忠实读取原材料，不能把文档没有的数字、记录或结论说成文档已经提供。后续生成草稿是独立能力，不能因资料缺少某个过程就停止整篇编写。

- 允许先生成完整章节结构、分析假设、拟议措施、过程表格，以及结合场景的候选内容，供作者逐章判断；重点支持要因确认、对策实施和效果检查的论证组织。
- 需要具体数值来讨论方案时，可生成明确标注的模拟或情景数据，记录适用条件和假设，并与资料事实、计算结果、实际记录分开。缺少的实际值仍标为待补或待核实，不能将模拟值自动登记为实测。
- 原材料中的数字、日期、调查、验证、实施和改善结果不因增强表现而改写；更正误写、统一单位或重新计算应保留原值、依据及差异。估测与实测、对照组与前后对比、原材料检测与实施后检测不可直接互换。
- 计算值提供输入和计算依据；建议目标、情景预测与实际结果明确区分。一个平均值不能反推出各测点的真实明细。
- 资料之外的外部案例、统计和规范不得冒充本项目事实。
- 回答提供可核对的文件名、页码／工作表／幻灯片及原文依据；网页资料提供来源链接。
- 区分资料已读取、本次提供给模型的资料和结论实际引用的证据。
- 来源冲突和证据不足必须显式呈现；仅靠提示词约束不足，应增加结果校验和证据检查。

草稿可在证据不齐时继续生成，但作者认为写法合适不等于记录已经发生。内容形成、作者审核、事实核实分别管理，具体见7.4节；导出草稿也应保留假设和模拟内容的性质标识。标准没有统一规定中间数据的具体数值，并不取消其客观事实和记录真实性要求。

### 5.3 角色模型与对话存档【已确认要求】

课题顾问聊天当前调用默认主模型，“选题评估”角色只作用于 SMART 评估。需修正配置与实际调用关系，明确顾问和评估的模型归属。

按项目持久保存完整聊天记录、引用和关联资料版本。刷新、离开或重新打开后恢复，修改课题不自动抹掉历史讨论。

### 5.4 依据上传 QC 规范评估【已确认要求】

当前命名检查三点是固定页面提示，不是动态检查；SMART 为模型按固定五维提示评分，未绑定明确规范条文。

目标要求：

- 优先识别并采用用户上传 QC 规范的适用要求，形成检查依据。
- 逐项呈现符合、不符合或证据不足，附条文位置、判断理由与修改建议。
- 规范没有评分规则时，不自行编造评分体系；SMART 只能作为明确标注的补充建议。
- 本次所读2020版附录 B 确有现场评审和成果评审分值，属于资料性参考；具体分值见第十章。不能将“规范没有评分规则”的条件句误读为本文件没有评审表，也不能将 SMART 五维评分冒充标准评分。
- 多份规范版本或要求冲突时提示，由用户确定适用依据。
- 命名检查与实际评估依据一致，不能继续将静态提示表现为已执行的检查。

### 5.5 少资料／无资料起步与场景框架【已确认要求】

支持三种入口：作者直接指定课题；作者指定业务与方向，由AI提出多个候选课题；作者与AI讨论后确定课题。无资料时根据作者指定的场景建立框架并联网，少资料时先读取已有材料再补充检索，不要求作者预先整理成完整数据集。

AI先提出详细的场景框架、候选条件及依据，作者选择、补充或纠正；已有信息直接复用，不要求从空白表格逐项填写。以下维度按课题适用性展开，不相关项可以跳过：

| 维度 | 需要说明和检索的内容 |
|---|---|
| 地域与地形 | 地点、地形、海拔或流域特征；外部案例与本地条件是否相近 |
| 环境与时间 | 季节、气候、汛期、土壤、水文、施工或作物生长周期；资料时期是否适用 |
| 工作对象 | 工程、设备、作物、工序或服务对象及边界；规格、品种和范围是否一致 |
| 现状与目标 | 问题表现、指标定义、单位和分母、目标来源、比较口径及对标依据 |
| 人员与组织 | 岗位、技能、人数、职责及协作方式；先采用作者确认的信息，缺项可作为假设条件，不能捏造具体人物的经历和行为 |
| 资源与工艺 | 材料、设备、预算、现场条件、可采用措施及实施限制 |
| 资料与不确定性 | 已有事实、外部参考、可计算信息、假设及待核实事项；来源冲突和适用限制 |

候选课题应说明与场景的关系、主要指标、现有依据和需要进一步核实的问题。课题确定后，检索仍随章节需要继续，不只在选题时执行一次。网络资料提高方案合理性和论证充分性，不能自动证明本项目发生过某次采样、检测或施工。

## 六、修改课题、保留数据与重置

当前只要课题文字改变，就清除后续数据关联及研讨、图表、PPT 状态，未区分改名与实质变更。

已确认要求：

- 仅调整名称措辞时默认保留数据，更新标题并提示受影响成果。
- 研究方向发生变化时展示影响范围，由作者决定保留调整、选择性重置或全部重置。
- 允许已有数据修改、复用或用于新的分析，不因更名强制全部重新上传。
- 受影响成果标记待复核，不能把旧结果直接当作新课题已验证结论。
- 重置与版本恢复方案需保护历史工作；保留可恢复版本为建议实现方式。

## 七、逐章编写、资料数据与审核流程重构【方向已确认，适用版本及详细方案待核定】

### 7.1 当前主要问题

- 当前仅维护一份数据关联，缺少阶段用途、采集时间和证据类型管理。
- 数据页只支持 CSV/XLS/XLSX，Excel 仅读取第一个工作表，不能直接编辑单元格。
- AI 清洗顾问仅看数据画像、问题数量和部分示例，没有读取完整表格或结合 QC 规范。
- 缺少清晰的修改前后对照、单步撤销；勾选但未应用的规则容易被误认为已生效。
- 一轮研讨和一份数据不足以支撑完整 QC 活动，尤其不能代替现场要因验证及实施后效果检查。
- 当前研讨入口要求已确认的数据集，缺少数据会返回数据页；数据页确认后直接进入研讨。这个前置条件不适合少资料／无资料开始讨论或编写，不能只移动“数据”菜单位置解决。静态代码依据为`frontend/src/hooks/useWizardGuard.ts`、`frontend/src/pages/DataPage.tsx`、`frontend/src/pages/DiscussionPage.tsx`及`backend/app/services/discussion_session.py`。

### 7.2 已确认的业务原则

- 各阶段均可产生、补充、引用数据和资料，不将数据集中限定在选题之后的单一入口。
- 现状调查、原因分析、要因确认、对策实施、效果检查等阶段的数据目的不同，必须区分。
- 资料不足可以先写框架、分析假设、拟议实施过程及标注性质的情景草稿，不因缺少一份Excel或现场记录阻止后续章节编写。
- 原因分析提出可能原因；缺少实际确认记录时可以讨论确认方案或模拟示例，但不能将其标成事实已核实的要因。
- 对策方案不等于已实施；可以先写实施章节草稿，不能以作者认可写法代替实施完成的事实依据。
- 没有实施后数据时可以开展效果预测或情景分析，不能认定实际目标已达成；比较需明确时间、对象、指标、单位及统计口径。
- 图表随章节需要生成，数据与文本同源；最终报告汇总已审核内容并保留相应事实、计算、假设或模拟标识。
- 显示缺项并允许“保留待核实项，继续下一章”；不将生成的模拟记录冒充实际工作记录。具体生成边界见5.2节。

### 7.3 逐章生成与审核节奏【已确认要求】

按“本章草稿—主要依据—需要作者决定的事项”集中呈现，提供通过、修改、继续讨论的操作方向，不必整篇写完才审核，也不逐句打断作者。

| 内容类型 | 审核方式 |
|---|---|
| 已确认信息的整理、格式调整和重复引用 | 自动处理，集中展示，可批量通过；不改变事实含义 |
| 背景介绍、过渡文字等简单内容 | 生成后允许快速通过 |
| 选题、目标、症结、要因、关键对策和效果结论 | 突出依据、推导和缺项，重点审核后确定当前章节写法 |
| 新假设、模拟数据、来源冲突及影响结果的清洗 | 明确提示性质和影响，由作者判断是否保留在草稿中 |

作者可以保留待核实项继续写作。后文与前文矛盾时，定位受影响的文字、数据、图表和章节重新复核，保留已完成工作，不让整篇无差别重审。简单内容可快速通过，不代表未经核实的事实自动通过。

### 7.4 内容、审核与事实状态分开【已确认要求】

| 状态维度 | 含义 | 不代表什么 |
|---|---|---|
| 内容已形成 | 章节已有文字、表格、图表和分析 | 不代表依据完整或现场已实施 |
| 作者已审核 | 作者认可当前写法、方案或草稿内容 | 不自动证明测量、试验或实施真实发生 |
| 事实已核实 | 相关记录、数据与经过有可核对依据 | 不自动证明全文计算、归因或标准符合性均正确 |

例如只有客土改良设想时，可以先生成实施章节的方案、检查项目和模拟示例；作者通过后可继续编写效果分析草稿，但实际实施及效果仍保留待核实状态。章节完整、审核完成、事实证据完整分别检查，不能用一个“已完成”状态合并。

### 7.5 活动时间、过程数据与结果关系【已确认要求】

软件不必同步现场进度，但报告必须说明何时开展活动、当时条件、过程数据如何变化及其对结果的影响。资料上传时间和作者编辑时间不能替代实际采集、实施或观测时间。

- **先后顺序**：调查、目标设定、要因确认、对策实施、效果检查及巩固观察应与所述活动路径衔接；后补录资料按实际发生时间归属，不能因上传较晚改变事实日期。
- **合理间隔**：结合地域、季节、施工周期、作物生长周期和技术条件判断措施生效所需时间；不能刚实施即无依据地声称得到长期效果。
- **数据归属**：每组数据对应时间、地点、对象、采样方法和措施；实施前、实施后、对照组及不同环境条件不可混用。
- **过程与结果**：区分对策自身目标和课题总目标，展示变化量、计算依据及推导关系，判断过程改善是否足以支持最终结果。
- **影响程度**：多项措施同时实施时，没有依据不得分别分配贡献率或将全部增益归于单项措施；区分观察到的变化与因果判断，并提示其他可能影响因素。
- **跨章一致**：计划与实际记录分别保留，检查正文、表格、图表、附件的日期与数值；修改时间或数据后提示受影响内容复核。

假设时间和模拟过程数据可用于草稿讨论，但应保持相应标识；合理性检查不能被表述为事实真实性验证。审核除“写法是否合适”外，还检查“时间是否合理、数据是否对应、结论是否得到支持”。

### 7.6 资料与编写顺序

持续开展的项目可以逐步积累材料；已完成项目可以先导入全部研究总结、验收材料和照片，再按章节整理。不强迫作者按页面顺序重复已做过的工作，也不要求把全部文字资料先转换为Excel。

默认沿章节顺序引导，但允许返回修改、补充和继续讨论。资料池、清洗、检索、分析和图表应是各章节可调用的能力；配置作为软件设置，与QC活动步骤区分。最终页面数量及导航形式仍待详细设计。

### 7.7 仍需详细设计或核定

1. 适用标准版本、申报附加规则；按第十章程序设计阶段进入与完成要求，以及跨阶段返回修改方式。
2. 将第十章证据要求落实为事实核实与标准检查项，分别设计草稿可继续、作者审核和事实核实的条件，不能一律设为开始写作的门槛。
3. 数据集与阶段的多对多关联、跨阶段复用和改进前后对比规则。
4. 现场确认记录、实施记录和附件的录入方式。
5. 将5.2节及7.3—7.5节落实为角色职责、审核交互、状态保存和时间／数据／归因检查；不能把已确认的审核方向继续写成完全待定。
6. 多表读取、数据编辑、清洗留痕、版本恢复和大文件处理方案。
7. 图表类型、报告章节、PPT 排版及规范符合性检查。
8. 旧项目、旧数据、旧对话与新流程的迁移策略。

以上事项已在1.1节任务包中补充拟议接口、职责、文件归属及验收条件；最终数据库结构与公共契约须在实施前统一冻结，适用版本等业务待核实项仍单独核定，不自动确定页面数量或实现排期。

## 九、核心验收原则

- 实际模型调用、搜索及文档解析需使用真实服务或真实样本验证；模拟测试不能替代真实能力证明。
- 已保存、已读取、已引用、已验证、已实施、已达标必须具有相应证据，不得混用状态。
- 少资料或无资料可进入选题和章节编写；没有完整Excel或现场记录不应阻断草稿。作者审核通过与事实核实分别记录。
- 清洗前后差异、资料推荐归属、计算依据、假设及模拟数据性质可核对，正文和图表不得静默改换数据含义。
- 逐章审核支持简单内容快速通过；时间顺序、效果观察间隔、对象口径和措施影响程度可检查，修改后只复核受影响内容。
- 未保存操作、大文件异常、资料识别失败、搜索失败和证据不足均有明确反馈。
- 未实现或尚未验证的能力如实标注，不以界面展示代替功能完成。
- 数据及后续阶段的最终验收以用户提供的 QC 规范和确认后的详细方案为准。

### 10.2 QC成果编写的根本要求【标准依据】

依据引言0.2、术语3.1—3.4及附录 B，QC成果应建立在小组实际开展的改进或创新活动之上，遵循 PDCA，以客观数据和事实调查、分析、评价、决策，适宜、正确地使用统计方法。报告要真实、有逻辑、通俗易懂，以图表和数据为主；文字润色不能代替调查、试验、实施和效果验证。

应区分以下三个层次：

1. **活动事实**：真实小组、真实问题或需求、原始记录、措施实施和实际结果。
2. **分析论证**：从资料和数据推导症结、提出原因、确认主要原因或比较创新方案，保留推导依据。
3. **成果表达**：按适用程序组织文字、图表和附件，保证报告与活动记录一致。

对于本项目，AI可以辅助整理、计算、分析、提示缺项、生成草稿；不能充当现场测量、试验、实施人员或审批部门。多个模型达成一致也不能替代现场证据。

本节保留标准本身的要求；它不等于软件必须在证据齐全后才能开始写作。软件允许按第五、七章规则先形成待核验或情景草稿，内容完整和作者审核通过不能直接解释为标准符合性已经成立。

### 10.3 三条活动路径【2020版标准依据】

**问题解决型／自定目标**（4.1.1及图2，PDF第9—10页）：

选择课题 → 现状调查 → 设定目标 → 原因分析 → 确定主要原因 → 制定对策 → 对策实施 → 效果检查 → 制定巩固措施 → 总结和下一步打算。

**问题解决型／指令性目标**（同上及4.1.3—4.1.5，PDF第10—11页）：

选择课题 → 设定目标 → 目标可行性论证 → 原因分析 → 确定主要原因 → 制定对策 → 对策实施 → 效果检查 → 制定巩固措施 → 总结和下一步打算。

自定目标路径不单列“目标可行性论证”，但目标仍需有设定依据；指令性目标路径不单列“现状调查”，但论证时仍可把握现状、找出症结，不能解释为不需要现状数据。课题来源中的“指令性、指导性、自选性”与目标来源中的“自定、指令性”是不同维度，不应仅凭课题由谁提出就自动确定程序。

**创新型**（4.2及图3，PDF第13—14页）：

选择课题 → 设定目标及目标可行性论证 → 提出方案并确定最佳方案 → 制定对策 → 对策实施 → 效果检查 → 标准化 → 总结和下一步打算。

创新型针对现有技术、工艺、技能、方法不能满足需求，通过新思维研制产品、服务、方法、软件、工具或设备等。不能仅因使用了AI、新设备或新称谓就认定为创新型。其核心是需求、借鉴、方案展开与事实数据比较，不应硬套问题解决型的“原因分析—要因确认”。

图2、图3均包含效果未达目标后返回分析或方案环节的反馈回路。软件可以合并页面展示，但不应合并证据状态，更不能在未达标时自动生成达标结论。

### 10.4 问题解决型各阶段要求及材料清单

下表“标准要点”为2020版原文归纳；“材料建议”为落实条文所需的建议记录形式，不表示标准规定了统一表名、字段或软件界面。

| 总结和下一步打算，4.1.12，PDF第12页 | 回顾专业技术、管理方法、成员综合素质等方面，提出下一次活动课题 | 有事实支撑的收获、不足和后续课题建议；未确定事项标明建议，不制造完成记录或能力评分 |

本版5W1H的对应关系为：What（对策）、Why（目标）、Who（负责人）、Where（地点）、When（时间）、How（措施）。不能只有一句措施描述就称为完整对策表。

### 10.5 创新型补充要求【标准依据，是否实施待确认】

依据4.2.2—4.2.9（PDF第13—14页）：

- 选题围绕未满足的需求，通过广泛借鉴形成创新思路，名称直接描述研制对象；必要时论证课题可行性。
- 目标与需求一致、可测量可检查、数量不宜多；依据借鉴的相关数据以及事实数据进行定量论证。
- 提出可能实现目标的各种方案，区分总体方案与分级方案；总体方案有创新性和相对独立性，分级方案具有可比性。
- 方案逐层展开至可实施的具体方案，依据现场测量、试验和调查分析得到的事实数据，逐个评价选择；不能用AI偏好或无数据的打分表代替比较。
- 将选中的具体方案逐项纳入5W1H对策表，逐条实施并检查相应目标；未达到时修改措施继续实施，必要时检查负面影响。
- 全部实施后检查课题目标，必要时确认经济和社会效益。
- 标准化先评价推广应用价值：有推广价值的形成技术标准或管理制度；专项或一次性成果整理创新过程资料归档，不能一律写成必须全面推广。
- 从创新角度总结技术、方法、成员素质的提升及不足，提出下一次活动课题。

### 10.6 统计方法、图表与成果表达【标准依据／建议方案】

### 11.3 后续设计应落实的证据关联【建议方案】

建议形成“问题或需求 → 现状及目标 → 症结／创新方案 → 末端原因及确认／方案比较 → 对策 → 实施记录 → 效果数据 → 巩固或标准化 → 报告引用”的关联。至少需要表达：

- 分析结论关联原始证据和计算过程；未确认推断、已核实事实、建议和待补信息分开。
- 要因逐条确认、对策逐项实施、效果按目标比较；对证据缺失与确实不适用分别处理。
- 数据修改后的下游待复核状态，以及多轮实施、复查和未达标返回记录。
- 小组及活动基本信息、活动记录、必要的审批和效益认可材料；AI聊天记录不能冒充成员真实活动记录。
