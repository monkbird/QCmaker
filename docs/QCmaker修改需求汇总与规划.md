# QCmaker 修改需求汇总与规划

## 一、文档定位与实施边界

本文汇总本轮项目核查和用户已确认的修改要求，作为后续实施依据。本文描述的目标能力尚未实现，不能作为当前功能说明或验收通过证明。

本次仅整理文档，不修改业务代码。配置、资料读取及选题相关要求先行明确；数据及后续流程涉及整体重构，待用户提供 QC 规范后，先核对规范，再制定详细方案，由用户安排实施。

需求状态分为：**已确认要求**、**建议方案**、**待规范明确**。建议方案不得视为用户已经确认的最终交互设计。

## 二、总体调整方向

现有“配置—选题—数据—研讨—图表—成果”六步工作台，将多个 QC 活动阶段压缩到同一数据和研讨流程，不能充分表达阶段证据、现场验证和实施后的效果检查。

已确认：按问题解决型 QC 的实际活动过程重构业务流程。数据、资料、分析和图表应服务于各阶段，而不是要求一次上传数据后自动推导完整成果。

用户提出的流程基线为：确定课题、现状调查、设定目标、原因分析、要因确认、制定对策、对策实施及效果检查、巩固措施和总结展望。具体阶段划分、名称、要求及成果结构，待上传规范核定。暂不确定最终页面数量，也不强制保留六步结构。

## 三、配置界面修改

### 3.1 多套配置与持久保存【已确认要求】

当前配置通过手动保存写入后端配置文件，只保存当前值；主模型、凭据库、角色分工各有保存按钮，没有多套方案切换，也没有未保存草稿保护。

目标要求：

- 支持整套配置命名保存、选择和切换，重新打开后恢复当前方案。
- 配置方案涵盖默认模型、角色模型分工、服务配置及搜索配置的关联。
- 明确当前方案、已保存状态和未保存变更，避免误以为“保存并继续”已提交所有分区。
- 密钥不回显，存储位置说明应符合实际部署；远程部署不得继续笼统声称“只存本机”。

建议方案：统一保存入口；切换前处理未保存内容；方案引用独立凭据记录，避免无必要复制密钥。历史版本、方案删除和恢复方式在实施设计时确定。

### 3.2 Coding Plan 与可选默认模型【已确认要求】

当前允许在主模型位置选择部分 Coding Plan 服务，但仅配置凭据库和各角色、主模型留空时，会被就绪状态及流程门禁挡住。部分无角色调用仍依赖默认主模型。

目标要求：

- 可以先保存 Coding Plan／服务配置，再给各角色选择该服务可用的模型。
- 默认主模型改为可选；未配置默认模型时，按实际业务环节检查角色是否完整。
- 配置缺失时指出具体角色或能力，不再统一要求填写 OpenAI Key。
- 审计所有模型调用入口，消除角色已分配但实际仍使用默认模型的隐式依赖。
- 资料基本读取不以套餐提供向量化能力为前提；需要向量化时独立检查相应能力。

套餐接口、模型列表和实际调用能力需实测，不能凭服务商已被收录就认定可用。模型接口适配范围在实际接入时核定。

### 3.3 模型清单与统一调用验证【已确认要求】

当前服务商名称及默认地址为预置目录，模型 ID 向服务商 API 获取；角色列表可能使用当前页面缓存。列表返回成功不代表账号有权调用全部模型。

目标要求：

- 保留底部“测试连接”作为统一测试入口，不新增角色旁的调用测试按钮。
- 对当前分配给所有角色的模型及已配置的默认模型发起真实最小请求。
- “跟随默认模型”的角色也纳入检查；全部角色通过才能显示整体通过。
- 显示每个角色对应的服务、模型及测试结果，失败时说明具体原因。
- 相同服务地址、凭据和模型的请求可合并测试，结果映射回各角色。
- 测试基于当前待保存配置；配置变更后旧结果不能继续代表新配置已通过。
- 未选用的模型不批量调用；明确真实调用会产生少量消耗。

用户已明确不加入上一轮提出的“角色刷新按钮强制重新拉取并显示获取时间”修改项。

### 3.4 Tavily 与联网检索【已确认要求】

当前 Tavily 已有实际搜索调用代码，但缺少真实密钥环境的成功验证；研究员会调用搜索，选题顾问尚未接入。无密钥或搜索失败时返回空结果，前端无法充分辨别原因。

目标要求：提供申请入口、明确搜索服务状态和真实搜索验证；区分未配置、调用失败及无匹配结果。用户不需要提供自有网站或目标网址。

无资料时必须联网检索，因此搜索不可用不能被包装成“无资料但仍有可靠事实结论”。搜索验证与模型连接测试属于不同能力，应分别呈现结果。

## 四、上传资料与中文完整读取

### 4.1 当前缺口

- 现有解析支持 DOCX、XLS/XLSX、PPTX、PDF、TXT、Markdown、CSV，但主要提取文本和部分表格。
- 扫描页、图片文字、图表视觉含义等未完整覆盖；旧版 DOC/PPT 不在支持范围。
- 表格资料存在行数截断；上传入库还依赖向量化服务。
- 不能将格式允许上传、解析未报错或成功切分，等同于内容完整且正确。

### 4.2 目标要求【已确认要求】

- 上传后直接读取，基本阅读不依赖向量化服务。
- 对已承诺支持的文档，完整处理正文、表格、备注、扫描页、图片文字等内容；长文档分批处理，不静默截断或遗漏。
- 针对中文编码、字体映射、扫描质量及复杂表格选择合适解析路径，必要时使用 OCR 或视觉识别交叉核对。
- 提供解析预览和来源定位，检查乱码、漏字、错行、表格错位及未解析区域。
- 遇到异常自动尝试其他可用方式；仍不可靠时明确定位，不猜补，不标为成功读取。
- 保留原始资料，派生文本和结构数据可追溯、可重建。

用户的验收目标是“全部内容读取正确”。实施方负责技术方案，不要求用户选择解析工具。不能以安装一个 skill 代替应用能力实现，也不能在未经核验时保证任意文件绝对无误。

建议验收方法：建立中文文档样本集，涵盖不同字体、编码、扫描件、混排及复杂表格，逐页或逐表核对内容覆盖与准确性。具体样本和受支持格式清单在实施前明确，旧版 DOC/PPT 是否补齐应列入覆盖范围讨论。

### 4.3 解除文件大小限制【已确认要求】

- 取消参考资料上传的 ≤10MB 限制，同步检查前端、后端、部署层及界面说明。
- 大文件显示上传和解析进度；失败给出原因，不用静默截断替代完整处理。
- 取消固定限制不等于忽略实际资源边界；大文件的流式处理、分批解析与恢复机制需在实施方案中落实。
- 数据页另有 10MB、5000 行、200 列及 Excel 解压大小限制，需在数据模块重构时统一审视；本轮明确取消的是参考资料上传的 10MB 限制，不将其他限制的具体处理方式视为已定。

## 五、选题顾问与证据约束

### 5.1 全文阅读与资料优先【已确认要求】

当前每次提问仅检索最多三个片段，每片段最多取三百字符，不是全文阅读。检索异常时仍可继续生成回答。

目标要求：

- 先完成全部上传资料的读取，再作答；长资料分批阅读并建立可追溯的来源索引。
- 将资料解析完成、内容阅读完成和本次回答采用的证据分别记录，不能用切片数量冒充全文理解。
- 当前资料未读完或存在解析失败时明确告知，不能声称已经完整阅读。
- 优先使用用户资料；没有资料必须联网搜，资料不足时联网补证并区分来源。
- 搜索失败或证据不足时说明限制、提出需要补充的信息，不生成假装经过查证的事实结论。
- 不重复无必要的全文读取：可复用已经核验的资料版本和阅读记录，但新增或修改资料必须重新处理相应内容。

### 5.2 禁止虚构、引用可核对【已确认要求】

- 禁止编造项目数字、日期、调查记录、要因验证结果、实施记录和改善效果。
- 缺失信息标为待补充；计算值提供输入和计算依据；建议目标与实际结果明确区分。
- 资料之外的外部案例、统计和规范不得冒充本项目事实。
- 回答提供可核对的文件名、页码／工作表／幻灯片及原文依据；网页资料提供来源链接。
- 区分资料已读取、本次提供给模型的资料和结论实际引用的证据。
- 来源冲突和证据不足必须显式呈现；仅靠提示词约束不足，应增加结果校验和证据检查。

### 5.3 角色模型与对话存档【已确认要求】

课题顾问聊天当前调用默认主模型，“选题评估”角色只作用于 SMART 评估。需修正配置与实际调用关系，明确顾问和评估的模型归属。

按项目持久保存完整聊天记录、引用和关联资料版本。刷新、离开或重新打开后恢复，修改课题不自动抹掉历史讨论。

### 5.4 依据上传 QC 规范评估【已确认要求】

当前命名检查三点是固定页面提示，不是动态检查；SMART 为模型按固定五维提示评分，未绑定明确规范条文。

目标要求：

- 优先识别并采用用户上传 QC 规范的适用要求，形成检查依据。
- 逐项呈现符合、不符合或证据不足，附条文位置、判断理由与修改建议。
- 规范没有评分规则时，不自行编造评分体系；SMART 只能作为明确标注的补充建议。
- 多份规范版本或要求冲突时提示，由用户确定适用依据。
- 命名检查与实际评估依据一致，不能继续将静态提示表现为已执行的检查。

## 六、修改课题、保留数据与重置

当前只要课题文字改变，就清除后续数据关联及研讨、图表、PPT 状态，未区分改名与实质变更。

已确认要求：

- 仅调整名称措辞时默认保留数据，更新标题并提示受影响成果。
- 研究方向发生变化时展示影响范围，由作者决定保留调整、选择性重置或全部重置。
- 允许已有数据修改、复用或用于新的分析，不因更名强制全部重新上传。
- 受影响成果标记待复核，不能把旧结果直接当作新课题已验证结论。
- 重置与版本恢复方案需保护历史工作；保留可恢复版本为建议实现方式。

## 七、数据及后续流程整体重构【待规范明确】

### 7.1 当前主要问题

- 当前仅维护一份数据关联，缺少阶段用途、采集时间和证据类型管理。
- 数据页只支持 CSV/XLS/XLSX，Excel 仅读取第一个工作表，不能直接编辑单元格。
- AI 清洗顾问仅看数据画像、问题数量和部分示例，没有读取完整表格或结合 QC 规范。
- 缺少清晰的修改前后对照、单步撤销；勾选但未应用的规则容易被误认为已生效。
- 一轮研讨和一份数据不足以支撑完整 QC 活动，尤其不能代替现场要因验证及实施后效果检查。

### 7.2 已确认的业务原则

- 各阶段均可产生、补充、引用数据和资料，不将数据集中限定在选题之后的单一入口。
- 现状调查、原因分析、要因确认、对策实施、效果检查等阶段的数据目的不同，必须区分。
- 原因分析提出可能原因；没有确认记录不得认定为要因。
- 对策方案不等于已实施；没有实施记录不得表述为实施完成。
- 没有实施后数据不得认定目标达成；比较需明确时间、指标、单位及统计口径。
- 图表随阶段需要生成，最终报告汇总各阶段已确认成果及引用证据。
- 缺什么就提示缺什么，不用 AI 生成内容补造实际工作记录。

### 7.3 收到规范后需要确定

1. 阶段结构、适用条件、进入与完成要求，以及跨阶段返回修改方式。
2. 各阶段资料、表格、图表和结论的必填项与证据要求。
3. 数据集与阶段的多对多关联、跨阶段复用和改进前后对比规则。
4. 现场确认记录、实施记录和附件的录入方式。
5. AI 在各阶段的职责、人工确认点及禁止自动推断的边界。
6. 多表读取、数据编辑、清洗留痕、版本恢复和大文件处理方案。
7. 图表类型、报告章节、PPT 排版及规范符合性检查。
8. 旧项目、旧数据、旧对话与新流程的迁移策略。

以上仅确立调整方向，暂不落定最终数据库结构、接口、页面拆分或实现排期。

## 八、建议实施顺序

| 顺序 | 工作包 | 前置条件 | 主要验收结果 |
|---|---|---|---|
| 一 | 核定需求与 QC 规范 | 用户提供规范并安排实施 | 形成有条文依据的流程与验收清单 |
| 二 | 配置方案、角色路由与统一测试 | 明确实际套餐和服务接口 | 多方案可恢复切换，全部角色真实调用结果可查 |
| 三 | 完整解析与证据基础 | 文档样本及格式范围明确 | 内容可核对，异常无静默遗漏，大文件可处理 |
| 四 | 选题顾问、规范评估与存档 | 解析、引用及搜索能力可用 | 资料优先、缺资料联网、引用可查、对话可恢复 |
| 五 | 分阶段 QC 流程与数据管理 | QC 规范及详细设计确定 | 各阶段证据完整，支持复用、修改和人工确认 |
| 六 | 阶段图表与最终成果 | 阶段数据及结论稳定 | 图表和报告可追溯，不虚构过程和效果 |
| 七 | 回归与迁移验证 | 以上工作完成 | 旧数据保护、流程回退及真实业务样本验证通过 |

该顺序是规划建议，不代表已开始执行。配置等相对独立工作可在用户安排后先行，但不能为赶进度提前固化尚未核定的 QC 流程。

## 九、核心验收原则

- 实际模型调用、搜索及文档解析需使用真实服务或真实样本验证；模拟测试不能替代真实能力证明。
- 已保存、已读取、已引用、已验证、已实施、已达标必须具有相应证据，不得混用状态。
- 未保存操作、大文件异常、资料识别失败、搜索失败和证据不足均有明确反馈。
- 未实现或尚未验证的能力如实标注，不以界面展示代替功能完成。
- 数据及后续阶段的最终验收以用户提供的 QC 规范和确认后的详细方案为准。
