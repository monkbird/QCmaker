本目录将[修改需求总纲](../../../QCmaker修改需求汇总与规划.md)拆成可独立交接的任务包。**本次只完成文档；没有启动代码实施。** 文档中的任务、测试和迁移均为后续执行计划，未勾选不代表遗漏。

总纲负责业务要求、标准解读和已确认边界；各包负责拟议实现方式。工程设计不得覆盖业务要求。字段、接口、页面结构仍属建议，通过00前置核对后冻结；正式适用标准版本、创新型范围等仍按总纲核定。

## 2. 并发批次

按一个协调者加最多三个工作代理安排；不是把六份文档同时交给六个代理修改同一项目。

1. **前置批：00串行。** 核对实施时现状、冻结跨包契约、完成共享基础及开发库迁移，形成C0交付。
2. **第一批：01、02、03并发。** 03先做独立路径、审核和场景框架，消费已冻结替身；真实模型与资料联调等待01/02。各包内部任务按文档顺序推进。
3. **第二批：04进入空闲槽位。** 01或02完成后即可开始04；03未完成时只消费契约样例。协调者核对交付，不并发修改仍被领域包持有的文件。
4. **集成批：05串行接线。** 接入领域结果、迁移、路由、状态、跨包测试；问题退回所属包，修复文件先明确归属。

依赖关系：`00 → {01,02,03,04} → 05`。03真实联调依赖01/02；04真实联调依赖02/03。因此“可先写独立部分”不等于“可提前宣布全功能完成”。

## 5. 后续派工模板

下列模板仅供用户安排实施后使用，本次不发送实施任务：

```text
执行任务包：<包编号及文档路径>。
先阅读需求总纲、00公共约定及本包全文，确认C0记录与工作区状态。
目标：完成本包任务，保持总纲业务边界及冻结契约。
只修改本包明确归属的文件；共享文件只提交接线请求。
可以使用冻结样例推进独立部分，不能伪称真实接口已经联调。
先验证关键失败场景再实现，按本包规定验收；不重置用户资料。
交付：改动清单、任务完成项、契约版本、测试证据、接线请求及残留问题。
不自行扩大到其他任务包，不自行发布或迁移用户唯一数据库。
```

每次分派须将占位的包编号和路径替换成具体值。协调者维护“未开始/进行中/局部通过待集成/完成/受阻”状态，受阻须列具体依赖和不受影响的剩余工作。
