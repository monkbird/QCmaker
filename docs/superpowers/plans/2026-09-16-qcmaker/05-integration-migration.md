# 统一集成、迁移与场景验收 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将各领域包接入可恢复的QC编写工作台，验证存量项目兼容和完整用户流程。
**Architecture:** 协调者串行合并共享文件；后端SQLite与前端IndexedDB分别版本迁移；阶段快照驱动导航、图表及导出。
**Tech Stack:** SQLite、IndexedDB、FastAPI、React、pytest、Vitest、Playwright。
**Spec:** [需求总纲](../../../QCmaker修改需求汇总与规划.md) 全文，尤其第6、7、9及11.5；[公共约定](00-contracts.md)。

## Global Constraints

- 本轮仅完善文档，不实施迁移、不启动子代理改代码、不运行收费服务或提交Git。
- 下列是未来实施清单；“检查”“运行”等动作不表示本次已经执行。
- 集成者独占00列出的公共文件、既有跨域测试及E2E；各领域包只提交对接需求。
- 不覆盖用户已有未提交改动，不默认重置数据库、删除上传文件或清空历史项目。

## 1. I1：迁移和兼容

- [ ] 保存数据库及上传目录备份方案，先在副本验证；保留v1迁移原文与校验和，新增版本顺序迁移，失败回滚并报告。
- [ ] 注册01配置表、02资料与数据版本、03章节及依赖、04产物元数据；统一外键、索引、资源引用计数/保留策略，不让各模块启动时重复建表。
- [ ] 管理端配置仍需兼容：明确.env部署设置与数据库模型配置的归属；混合修改要保证失败后可恢复，不出现一半保存却向用户报成功。模型快照与预算/调用日志保持一致。
- [ ] 原dataset原始/当前值及confirmed_revision继续保留；已有“确认数据”只迁移为旧流程清洗确认，不能等同整章事实核实。旧根因字符串为待确认原因，旧研讨摘要作为导入草稿。
- [ ] IndexedDB在原v1基础上升级，保留项目和数据；新的chapterRefs、materialRefs、artifactRefs允许从旧dataRef平滑导入，不能靠清浏览器数据完成升级。
- [ ] 迁移可重复启动；新版本写入后回退旧程序的限制明确说明，通过备份恢复而非强行让旧代码读新库。测试失败不操作用户唯一数据库。

拟新增测试：`backend/tests/test_qc_migrations.py`、`frontend/src/test/qcMigration.test.ts`。断言包含旧库升级、二次启动、部分失败回滚、版本校验、资料引用TTL保护以及旧会话恢复。

## 2. I2：路由、公共状态与导航

- [ ] 在`backend/main.py`注册资料、章节及新报告接口，保持原认证、中间件、请求限制和管理端隔离。
- [ ] 检查上传限制的前端、后端、代理部署各层；取消参考资料10MB硬上限后仍保留解压炸弹、类型、超时及资源保护。过大文件可分阶段解析，不承诺无限资源。
- [ ] 合并公共types、API适配及WizardContext；保留现有“持久化成功后再发布状态”的提交机制，失败不误提示保存成功。
- [ ] 修改向导守卫：可先整理场景、资料和手动编辑，不必全部模型配置齐全；具体AI操作检查对应角色能力。无Excel及无确认dataset不得成为进入逐章编写的全局阻断。
- [ ] 导航按“项目/选题、资料、章节、图表、成果”等职责接入，章节内承载QC步骤；这属于建议交互布局，不把页面数写成标准要求。
- [ ] 接入名称轻改、范围实改的影响预览及局部重审，保留历史；恢复项目时校验服务端版本和本地缓存，旧结果不覆盖新状态。
- [ ] 将旧discussion入口与新的章节草稿边界明确呈现；真实活动记录、AI讨论、模拟情景不混为一种记录。

由本包修改00公共文件清单，并在必要时适配既有`frontend/src/test/wizardReducer.test.ts`、`wizardGuard.test.ts`、`projectRecovery.test.ts`及既有跨流程测试。领域包新增测试文件各自维护，避免双方同时改同一断言文件。

## 3. I3：必须走通的用户场景

| 场景 | 操作 | 验收结果 |
|---|---|---|
| 无资料 | 指定地区/场景，联网研究，选择课题，逐章生成 | 不要求Excel；来源和假设可辨；审核可分章 |
| 少资料 | 两份研究PDF进入资料区，清洗确认、推荐章节 | 原文保留；对照估测不自动改成前后实测 |
| 中文扫描标准 | 使用总纲记录的20页、12,905,586字节PDF | 上传不过早拒绝；逐页覆盖、图表脚注及失败页可查 |
| 关键过程缺证 | 生成要因、实施、效果草稿并接受表达 | 能继续，但状态不伪装事实完整 |
| 时间冲突 | 观察早于实施、不同采样对象或单位 | 显示可定位冲突，作者处理后局部更新 |
| 版本变化 | 修改一份资料或指标 | 只使相关结论/图表/报告待复核，旧版可查 |
| 配置切换 | 两方案、无默认但配置topic、草稿测试失败 | 正确角色路由，失败不污染已保存方案 |
| 刷新/断网 | 未保存、保存失败、任务进行中刷新 | 草稿/任务状态可恢复，无旧响应覆盖 |
| 导出 | 不同路径、缺章、模拟、多页图表 | 预检清楚，版本固定，标识保留，中文排版可读 |
| 隔离 | 其他项目资料ID/报告ID及未授权访问 | 拒绝访问，日志不泄露密钥或敏感全文 |

真实资料只在本地验收使用，不未经许可提交到仓库或上传外部服务。联网/模型请求复用已有配置和授权边界；离线替身通过与真实服务通过分别记录。
